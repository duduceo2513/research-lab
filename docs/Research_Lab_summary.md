# Research Lab — краткая сводка

Research Lab — система из 9 агентов. Преподаватель вводит тему, а система сама ищет материалы в 10 источниках, скачивает документы, читает их, отбирает надёжные, пишет лекцию и задание и проверяет результат отдельным проверяющим. Всё видно в интерфейсе в реальном времени и записано в журнал.

## Требования задания и что сделано

| Требование | Статус | Как сделано |
|---|---|---|
| **АГЕНТЫ** | | |
| Не менее 4 агентов, у каждого одна роль | Да | 9 агентов: 4 работают через LLM, 5 — обычные сервисы (поиск, загрузка, чтение файлов) |
| Описаны роль, входы, выходы, инструменты, критерий завершения | Да | Таблица агентов в подробном отчёте (раздел 4) |
| Роли не дублируются | Да | Веб-поиск и научный поиск различаются источниками; автор текста и проверяющий — разные агенты |
| Ни один агент не больше 40% вызовов LLM и инструментов | Да | В контрольном прогоне максимум 20% (раньше было 41%): источники проверяются пакетами по 4, загрузка и чтение файлов разделены на двух агентов |
| Не более 5 инструментов на агента | Частично | У поиска научных работ 7 источников (сознательно: больше источников — полнее материал). У остальных агентов не больше 3 |
| Оркестратор только планирует | Да | Boss — скрипт без LLM: порядок шагов, лимиты, отмена. Предметной работы не делает |
| **ВЗАИМОДЕЙСТВИЕ И ДАННЫЕ** | | |
| Схема взаимодействия показана на схеме | Да | Оркестратор + конвейер + цикл проверки; схема в docs/architecture.png |
| Структурированные сообщения (JSON / типизированные объекты) | Да | Типизированные объекты и JSON-события передачи работы |
| Не менее 2 внешних инструментов или источников | Да | 10 поисковых API, загрузка файлов, разбор PDF/PPTX/DOCX, Claude и локальная модель |
| Состояние задачи хранится явно | Да | База данных (в этой версии — SQLite) и файловое хранилище; после обновления страницы всё восстанавливается |
| **НАДЁЖНОСТЬ И БЕЗОПАСНОСТЬ** | | |
| Лимиты шагов и времени, защита от зацикливания | Да | Лимит шагов и 30 минут на запуск, не больше 2 доработок, кнопка отмены |
| Обработка ошибок: повторы, понятное сообщение | Да | Повторы запросов, сбойный источник пропускается, при недоступной модели — переход с локальной на Claude и обратно |
| Логирование всех вызовов агентов и инструментов | Да | Каждый шаг агента, каждый вызов инструмента (запрос и ответ в JSON), каждый вызов модели (токены, стоимость) |
| Ключи API не в коде | Да | Только в файле .env, он не попадает в репозиторий |
| Интерфейс CLI или веб | Да | Веб-интерфейс с графом агентов в реальном времени |
| **ЧТО СДАЁТСЯ** | | |
| Git-репозиторий и README | Частично | README обновлён; изменения этой доработки ещё не закоммичены |
| Схема архитектуры | Да | docs/architecture.png |
| Таблица агентов | Да | В подробном отчёте |
| Тестовые сценарии (4 / 6 / 10+) с ожидаемым результатом | Да | 12 сценариев в отчёте и 504 автотеста. Живые прогоны есть только по нескольким темам |
| Логи типового прогона (подтверждают нагрузку) | Да | docs/run-18-report.md и .json (создаются командой research_report) |
| Отчёт 5–10 страниц | Да | docs/Research_Lab_report.docx, 6 страниц |
| Презентация до 10 слайдов | Нет | Не сделана |
| Тема согласована с преподавателем | Нет | Согласования не было, документ написан на согласование |

## Что ещё не закрыто

- Презентация (до 10 слайдов) не сделана.
- Тема не согласована с преподавателем.
- Нагрузка измерена на одном полном запуске. Для экзамена нужны живые прогоны на 10+ темах.
